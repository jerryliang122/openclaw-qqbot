# 计划：asrFallback 非显式 true 时无条件丢弃平台 ASR 转写

## 语义变更（目标行为矩阵）

| 场景 | asrFallback | 平台转写（asr_refer_text） | 语音消息结果 |
|---|---|---|---|
| STT 配置解析成功 + 转写成功 | 缺省 / false | 丢弃（现状不变） | `[Voice message] <STT文本>` |
| STT 配置解析成功 + 转写失败/转空 | 缺省 / false | 丢弃（现状不变） | `[Voice message - transcription failed]` |
| **STT 未配置 / resolveSTTConfig 返回 null** | **缺省 / false** | **丢弃（本次翻转点）** | `[Voice message - transcription unavailable]` |
| 任意场景（含 STT 未配置） | **显式 true** | 保留 | 平台文本参与（旧行为，显式 opt-in） |

翻转点只有一个：`shouldUsePlatformAsr` 不再因 `!sttCfg` 放行（`stt.ts:33` 的 `if (!sttCfg) return true` 删除）。开关读取独立于 STT 凭证解析成败。

## 代码改动

### 1. `src/utils/stt.ts`
- 重写 `shouldUsePlatformAsr`（`stt.ts:32-35`），签名改为接收原始 cfg，直接读 `channels.qqbot.stt.asrFallback === true`，与 STT 凭证是否解析成功完全解耦：
  ```ts
  export function shouldUsePlatformAsr(cfg: Record<string, unknown>): boolean {
    const channels = asRecord(cfg.channels);
    const qqbot = asRecord(channels?.qqbot);
    return asRecord(qqbot?.stt)?.asrFallback === true;
  }
  ```
- 从 `STTConfig` 接口删除 `asrFallback` 字段（`stt.ts:17-24`），删除 `resolveSTTConfig` 中的读取与嵌入（`stt.ts:50-51`、`:64`、`:81` 两处返回对象）。开关的唯一事实来源变为上面的独立读取。
- 更新文件头与相关注释为新语义。

### 2. `src/middleware/attachment.ts`
- `processAttachments`（`:99` 附近）：新增 `const usePlatformAsr = shouldUsePlatformAsr(cfg);`，作为参数传入 `processVoiceAttachment`（`:122` 调用、`:210` 签名各加一个参数）。
- `:221` 改为 `const asrReferText = usePlatformAsr ? rawAsrText : undefined;`
- `!sttCfg` 分支（`:226-237`）结构不变（`asrReferText` 为 undefined 时自然落到占位文本），但新增一条 info 日志补上本次排查暴露的可观测性缺口——平台文本存在但被丢弃时必须可见：
  ```ts
  if (!sttCfg) {
    if (!usePlatformAsr && rawAsrText) {
      log?.info(`Voice: STT not configured; platform asr_refer_text discarded (asrFallback not enabled)`);
    }
    ...
  }
  ```
- 更新 `:216-219` 注释为新语义。

（`body-assembler.ts`、`voice-text.ts`、`ctx-builder.ts` 均无需改动：`- ASR:` 行随 `asrReferText=undefined` 自然消失，media facts 的 `transcribed` 随 `source==='fallback'` 自然省略。）
